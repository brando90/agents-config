## Trigger Rule 13

13. **Load ML writing guide for top-venue paper work.** _Trigger: any NeurIPS / ICML / ICLR-style paper work, including editing `.tex`, adding claims/numbers/tables, deciding which artifacts to cite or keep, or answering proof/result-validity questions._ Before acting, read [`writing/ml_research/ml_research_writing.md`](../writing/ml_research/ml_research_writing.md) and apply its Scientific Rigor and Sentence-Level Prose Discipline. For any sentence that ships in the paper, run the 4-check (read-aloud / claim-count / citation-count / word-count) while drafting, not during QA. Keep `.tex` prose **one sentence per line** (newline after every full sentence, no mid-sentence wraps; § LaTeX Source Layout; check with `python3 ~/agents-config/scripts/latex_sentence_lines.py --check FILE.tex`). Name data splits **train / validation (val) / test**, never "dev set" or "development panel" (§ Data-Split Names). Keep papers **one file per section** (`main.tex` = preamble + `\input` list; `00_abstract.tex` … `990_appendix_*.tex`) so parallel agents edit different files.

## Trigger Rule 35

35. **Every active paper dir keeps a freshly compiled PDF committed — recompile on every semantic `.tex` edit.** _Trigger: you make a **semantic** change to a paper's LaTeX sources (`.tex` / `.bib`, e.g. under `paper_latex_and_notes/` — the bucket was named `paper_latex/` before the 2026-09-12 rename in Rule 49) — a new or reworded paragraph, a figure/table/macro/citation added or changed, a section moved, anything that alters the rendered output. Not per-keystroke: cosmetic churn (a typo mid-sentence, whitespace) does not need its own build — recompile once the edit is semantically complete._ Rules:
    - **Committed PDF at the paper-dir root.** Every *active* paper directory ships a current compiled PDF next to its sources (e.g. `paper_latex_and_notes/ICLR_2027_VeriBench/00_main_iclr_2027.pdf`), tracked in git and readable from GitHub without a local toolchain. In a multi-venue repo **each active venue dir gets its own PDF** — one dir having a PDF does not cover the others.
    - **Same commit.** Any commit that changes `.tex` / `.bib` must include the rebuilt PDF in that **same commit**. A source commit with a stale or missing PDF fails this rule.
    - **Non-blocking.** Background the build and keep working; never foreground-wait on a compile. After a substantive edit, check the status/log (`_build/STATUS`, `_build/compile.log`) and fix any `FAILED` before reporting done. Also confirm the log is clean of `^!` errors and undefined refs/citations — exit 0 alone is not proof.
    - **Toolchain.** Prefer `tectonic` (self-contained, resolves the bibliography in one pass); fall back to `latexmk -pdf -interaction=nonstopmode -f -outdir=_build <main>.tex` when tectonic is absent. **Machines differ — always probe before trusting a documented command:** run `command -v tectonic || command -v latexmk` first. Brando's personal mac has TeX Live at `/usr/local/texlive/2024/bin/universal-darwin` (latexmk, **no** tectonic), so a tectonic-only script silently no-ops there; the Vals MacBook Air is the **opposite** — `tectonic` under the user's homebrew prefix and **no** TeX Live, where the documented `latexmk` line exits `127`, which reads like a LaTeX error but is a missing binary. **Also:** a repo's auto-compile hook is typically `PostToolUse` on the **Edit/Write tools only**, so editing a `.tex` through Bash (`sed`, a `python3` heredoc, a shell redirect) does not fire it and produces no PDF, silently — compile by hand whenever you edit LaTeX via Bash. Aux artifacts go to a gitignored `_build/` so only the tracked PDF changes.
    - **Writer-independent refresh on the Macs (Brando, 09-16-2026: "I want to read the most recent version always").** The PostToolUse hook fires only for a Claude session's Edit/Write tools; a Cursor save, a shell edit (`sed`, a Python script), a Codex edit, or a `git pull` does not trigger it. So each Mac also runs `scripts/paper_watch.py` as a launchd user agent (`bash ~/agents-config/scripts/install_paper_watch.sh ~/veribench [more repos]`; label `com.brando.paper-watch`, restarts on login and crash), which polls every `paper_latex*/<VENUE>/` every 2 s and, on any change to a `.tex`/`.bib`/style/figure file, feeds the change to that repo's compile hook (or runs `latexmk` itself when a repo has none), so every `00_main_*.pdf` next to the sources is current whoever changed the sources. Log: `~/Library/Logs/paper_watch.log`; status: `launchctl print gui/$(id -u)/com.brando.paper-watch`. Open the PDF in Cursor's viewer and it reloads on each refresh. Committing still requires the PDF to be current (same-commit rule above); the watcher makes that the default rather than a chore.
    - **Auto-compile hooks must be venue-agnostic.** A project PostToolUse hook (e.g. veribench's `.claude/hooks/compile_paper_on_edit.sh`) satisfies this rule only if it matches **any** `paper_latex_and_notes/<VENUE_DIR>/` — a hook hardcoded to one venue is a bug: new venue dirs then compile for nobody. When a hook covers the edit, just verify the PDF/status refreshed.
    - **Migrating a repo to this pattern:** add the `.gitignore` entry for `_build/` (and a `!<main>.pdf` negation if PDFs are ignored), and record the paper dir + main file in the project's `CLAUDE.md`.

    **Why:** on 2026-08-19 the new `paper_latex/ICLR_2027_VeriBench/` dir had **no PDF at all** — the repo hook matched only `paper_latex/NeurIPS_2026_VeriBench/` and called `tectonic`, which isn't installed on Brando's personal mac, so every ICLR edit compiled nothing and Brando had to ask for the PDF by hand. He wants the live Overleaf workflow: the PDF refreshes itself after each meaningful edit, and the repo always ships a readable, current PDF.

## Trigger Rule 40

40. **Every committed slide deck ships a synced PDF (and, for `.pptx`, a text dump) beside it.** _Trigger: you add, edit, or commit a `.pptx` / `.key` / `.ppt` / `.odp` slide deck in any repo — including a deck downloaded from Google Slides or Keynote and dropped into an experiment folder._ Binary decks are invisible inside Cursor / VS Code: the editor cannot render them, `grep` cannot read them, and `git diff` shows only "Binary files differ". So each committed deck carries generated siblings, regenerated from the deck and committed **in the same commit as the deck**:
    - **`<deck>.pptx.pdf`** — the rendered slides, for every deck format. Cursor opens these inline via the `tomoki1207.pdf` extension, so this is how a deck is actually *looked at* in the editor.
    - **`<deck>.pptx.md`** — a slide-by-slide text outline (titles, nested bullets, tables, speaker notes, image counts). **`.pptx` only:** `.key` is a proprietary format and `.ppt` / `.odp` are different containers, so those get the PDF and full freshness tracking but no text sibling. Keynote directory packages must first be exported as single-file `.key` decks; both checks reject package directories rather than silently omitting them. The text dump is what makes a deck greppable and gives it a **readable line-level `git diff`** instead of a binary blob.

    **Command:** `python3 ~/agents-config/scripts/sync_slide_decks.py` — with no arguments it syncs every deck under the current git repo root; `--check` verifies the working tree; `--check-staged` verifies **git's index** and is what the pre-commit hook runs; `--md-only` skips rendering when no converter is installed; `--force` regenerates everything. Python 3.8+ standard library only, so it runs on any machine with `python3` (no `pip install`, which matters under PEP 668).

    **Naming is `<full source filename> + .pdf` / `+ .md`**, keeping the deck's own extension in the middle — `Thesis Plan.pptx` → `Thesis Plan.pptx.pdf`. That survives filenames with spaces, parentheses, em-dashes and trailing spaces (Brando's decks have all four), makes the derivation unambiguous in both directions, and lets a repo un-ignore every derived deck PDF with one `.gitignore` line (`!**/*.pptx.pdf`) even under a blanket `*.pdf` ignore. **Keep deck extensions lowercase** — a case-sensitive repo would still ignore `.PPTX.pdf`; and a negation cannot reopen an ignored *parent directory*.

    **Freshness lives in a `.slide-sync.json` manifest at the repo root, which records the sha256 of the deck AND of each derivative — never mtimes, and never only a hash in the `.md` header.** Git does not preserve mtimes, so after a fresh clone every derivative looks newer than its source and an mtime check silently passes on stale files. A header hash in the `.md` is no better on its own: a `.pdf` cannot carry a provenance header and the non-`.pptx` formats have no `.md` at all, so `--md-only` (or a render that fails *after* the text was written) would leave a fresh hash sitting next to a stale PDF and the gate would call it in sync. **A manifest entry is written only after that derivative is successfully produced**, so a failed render leaves the gate red rather than green, and hashing each derivative also catches a truncated, hand-edited or replaced file. For the same reason `--check` always verifies the **full** derivative set: `--check --md-only` / `--check --pdf-only` are rejected rather than silently checking half of it.

    **The pre-commit gate validates the index, not the working tree, and reads filenames NUL-delimited.** A working-tree check passes while the commit itself carries only the deck — derivatives left unstaged — or carries a deck that differs from the one the derivatives were built from. And `git diff --cached --name-only` **quotes** any non-ASCII path: a deck named `… — Clear Metric Notation.pptx` arrives as `"… \342\200\224 … .pptx"`, whose trailing quote defeats a shell `grep '\.pptx$'`, so a filename-filtering hook silently never runs on exactly the decks Brando has. Renames matter too: `git mv` reports status `R`, which an `ACM`-only diff filter ignores. Hence `--check-staged` does the path handling in Python with `-z` and `--diff-filter=ACMRTDU` (including type changes and unresolved merges); Git inspection errors fail the check.

    **Renderer:** LibreOffice headless (`soffice --headless --convert-to pdf`, run against a scratch `-env:UserInstallation` profile so it never fights a running GUI instance, output staged to a temp file and moved into place) is the portable path — `brew install --cask libreoffice` on macOS, the distro package on Linux. The script's macOS Keynote/AppleScript fallback needs Automation permission granted interactively to the calling terminal (**System Settings → Privacy & Security → Automation**); without it AppleScript fails with `-600 Application isn't running`, which reads like a crash but is a permissions denial. **A deck is never edited through its derivatives** — edit the deck, re-run the syncer. Authoring a deck *as* text is a different workflow (Marp / `md` → `pptx`) and is not what this rule covers.

    **Setup in a new repo:** run `sync_slide_decks.py --install-hook`. It resolves the effective hooks directory via `git rev-parse --git-path hooks`, so `core.hooksPath` and linked worktrees (where `.git` is a *file*) work; it installs the logic as a standalone `slide-deck-sync-check` and, if a `pre-commit` hook already exists, **prints the one line to add rather than appending** — appending after an existing `exit 0` reports success while leaving the check unreachable. Add the `.gitignore` negations if the repo ignores `*.pdf`, and commit `.slide-sync.json`.

    **Why:** asked for by Brando 2026-09-08 — `experiments/23_thesis_plan_for_sanmi_and_azalia/(Final shown to Sanmi SK) - Thesis Plan Sept 4 2026 .pptx` was committed as a deck nobody could open, read, or review from the editor where the rest of the thesis lives, while `experiments/21_qual_exam_2026_slides/` had a *hand-exported* PDF and text dump that nothing kept in sync — the drift this rule removes. He asked for an editable view and accepted "the deck stays the source of truth, plus a PDF that is **always in sync, never behind**"; the manifest and the index-based hook exist because the first implementation of this rule shipped three separate ways to report "in sync" over stale output, all caught by Codex QA before the rule was trusted.

## Trigger Rule 60

60. **Load `technical-explainer-style.md` for explainers and teaching docs.** _Trigger: the deliverable's job is to make the reader understand something rather than to ship in a venue — explaining a concept, algorithm or derivation; notation references and translation tables between conventions; walkthroughs of a paper's method (including Brando's own); onboarding or internal teaching notes; or any request phrased as "explain in detail", "I don't know what X is", or "make the jump from A to B"._ Read [`writing/explanations/technical-explainer-style.md`](../writing/explanations/technical-explainer-style.md) into your context before acting. It specifies the two load-bearing mechanics (every section opens with a bolded claim-sentence, so the bold sentences alone carry the argument; equations self-annotate via `\underbrace{...}_{\text{plain English}}`), the prose rules (1–3 sentence paragraphs, second person, gloss every symbol on first use, announce notation collisions and why, pair each formula with a verifiable numeric micro-example, bolded question for the obvious objection, `TL;DR` at the bottom only), the equation rules (`\boxed{}` for definitions and results at roughly one per section, never intermediate algebra; display math on its own line; sandwich every equation with a sentence before and after; `\begin{aligned}` for derivation chains), the antipattern table, and a copy-paste prompt block for dispatching explainers to other agents. **Mutually exclusive with Trigger Rule 13:** `\boxed{}`, `\underbrace{}`, second person and TL;DR blocks read as lecture notes to a top-venue reviewer, so a doc in this style must be rewritten — not lightly edited — on the way into `.tex`. If a task turns out to be paper prose, drop this style entirely and load [`writing/ml_research/ml_research_writing.md`](../writing/ml_research/ml_research_writing.md) instead. Composes with Hard Rule 10 (expand acronyms/jargon on first use), Trigger Rule 16 (file-level `# Title` + `**Doc link:**` + `**TLDR:**` header, which is a summary and does not replace the bottom `TL;DR` compression), and Trigger Rules 23–24 (jargon stays out of reader-facing prose — an explainer is reader-facing even when the reader is Brando).
